# Маша — виртуальный турагент «Тотус клуб»

**История проекта, архитектура и решённые проблемы**

Текущая версия: `v34-destinations` · документ актуален на 3 августа 2026

---

## 1. Что это

Чат-виджет на сайте totus.club. Клиент описывает отдых обычными словами — Маша подбирает туры, показывает карточки отелей, рассказывает про отели и номера, отвечает на вопросы и ведёт на страницу бронирования.

Ключевой принцип: **все данные о турах, отелях, номерах и ценах приходят из партнёрского API Level.Travel**. Модель не придумывает ни одного факта — она формулирует ответы поверх реальных данных.

Второй принцип: **клиент никогда не видит поставщика**. Ни в тексте, ни в интерфейсе, ни в адресной строке. Для клиента это система бронирования «Тотус клуба».

---

## 2. Архитектура

```
Браузер (React)  ──WebSocket──►  Node.js сервер  ──►  DeepSeek V4 Flash (LLM)
                                       │
                                       └──────────►  Level.Travel API v3.7
```

**Стек:** Vite + React (фронтенд), Node.js + TypeScript (бэкенд), WebSocket для диалога, REST для служебных запросов.

**Подход:** function calling, а не дообучение модели. Модель получает набор инструментов и решает, какой вызвать. Прослойка исполняет вызов, ходит в Level.Travel и возвращает структурированный результат.

### Файлы

| Файл | Назначение |

## 3. Решённые проблемы

Самая ценная часть документа: каждая из этих ошибок стоила отдельного расследования.

### 3.1. Модель молча падала, отвечал скриптовый бот

**Симптом:** «перестал находить туры», в чате появлялись ответы вроде «Шаг 1/5 — напишите id тура».

**Причина:** две наложенные проблемы. DeepSeek V4 по умолчанию работает в режиме размышлений: `content` приходит пустым, весь текст в `reasoning_content`, и API **требует возвращать это поле обратно** в истории. Второй вызов после результата инструмента падал с `HTTP 400`. А ошибка глушилась в `catch` и включался старый скриптовый режим.

**Решение:** параметр `thinking: {type: 'disabled'}` — проверено живым тестом, остальные варианты не работают (`reasoning_effort:none` даёт 400, `enable_thinking:false` игнорируется). Молчаливый откат убран: ошибка теперь видна в чате. Флаг `LLM_THINKING=enabled` для возврата.

### 3.2. Проверка типов не смотрела на серверный код

**Симптом:** ошибка `apiTraceLength is not defined` в работающем приложении, хотя проверка проходила чисто.

**Причина:** `tsconfig.node.json` содержал `"include": ["vite.config.ts"]` — проверялся один файл конфига, папка `server/` не проверялась вообще.

**Решение:** создан `tsconfig.server.json` и команда `npm run typecheck:server`. Первый запуск нашёл три скрытые ошибки, включая `.filter()` на промисе без `await`.

### 3.3. Курорт терялся, если названа и страна

**Симптом:** запрос «Кемер» возвращал отель в Стамбуле.

**Причина:** словарь возвращал **первое** совпадение. В строке «Кемер, Турция» раньше находилось слово «турция» — курорт отбрасывался, поиск разворачивался на всю страну.

**Решение:** собираются все совпадения, выбирается самое специфичное. Курорт всегда бьёт страну.

### 3.4. Вылет из Санкт-Петербурга не работал

**Симптом:** поиск завершался за 0,3 секунды с нулём отелей.

**Причина:** Level.Travel пишет составные названия **через точку**: `St.Petersburg`, `Krasnaya.Polyana`. Отправлялось `Saint Petersburg` с пробелом — все операторы отбрасывали запрос.

**Решение:** правильные написания плюс загрузка справочника `/references/departures` при старте, чтобы написания больше не угадывать.

### 3.5. Один номер вместо тринадцати

**Симптом:** у отеля показывался один тип номера, на сайте totus.club — тринадцать.

**Причина:** нашлась при расшифровке `request_id` (это base64):

```
Страница отеля totus.club:  213|225|0|1056|9223758|2026-08-01,...
Наш поиск:                  213|225|0| 983|        |2026-08-11,...
                                            ↑ поле ID отеля
```

Сайт при открытии отеля запускает **отдельный поиск по одному отелю** и получает полный каталог. Мы переиспользовали `request_id` широкого поиска, где на каждый отель приходит пара дешёвых предложений.

**Решение:** тот же приём — отдельный поиск с `hotel_ids`. Позже (v29) сделан опциональным: он стоит 30–45 секунд, поэтому включается только по просьбе «покажи все номера».

### 3.6. Отель, вышедший из бренда, попадал в семейство

**Симптом:** в списке отелей Titanic появлялся Mardan Palace, который больше не принадлежит сети.

**Причина:** Level.Travel хранит прежнее имя в названии: `Mardan Palace (Ex. Titanic Mardan Palace)`. Совпадение находилось в пометке о **бывшем** названии.

**Решение:** `stripFormerName()` — сравнение по актуальному имени. Прежние названия используются запасным вариантом, если по текущим ничего не нашлось (клиент может искать по старой памяти).

### 3.7. Фильтр по удобствам не работал, но Маша о нём отчитывалась

**Симптом:** «все отели с аквапарком, как вы просили» — при том, что аквапарк никто не проверял.

**Причина:** модель передавала `features: ["аквапарк"]`, но параметр **не доходил до поиска** — молча отбрасывался. Из 1115 отелей 12 осталось из-за фильтров «5 звёзд» и питания.

**Решение:** фильтр реализован со словарём синонимов и **честной отчётностью**: если отфильтровать не удалось, модель получает `features_filter_applied: false` и запрет утверждать, что удобство есть.

### 3.8. Карточка отеля была почти пустой

**Симптом:** на вопрос про аквапарк Маша отвечала «судя по фотографии, аквапарка нет» — при том, что аквапарк есть.

**Причина:** две ошибки. Функция загрузки полной карточки начиналась с «если отель в кэше — вернуть кэш», а в кэш он попадает из поиска, где почти нет данных. То есть справочник **не запрашивался никогда**. Плюс богатые поля отбрасывались маппером.

**Решение:** справочник запрашивается всегда, из него берутся описание и полный список удобств. В промпт добавлено правило: **отсутствие данных — не ответ «нет»**, и запрет делать выводы «по фотографии».

### 3.9. Неизвестное направление молча становилось Турцией

**Симптом:** запрос про Японию возвращал турецкие отели.

**Причина:** нераспознанное направление подставлялось как `country: 'TR'`, а неизвестное слово — как **город в Турции** (`to_city="Япония"`).

**Решение:** подстановка убрана. Неизвестное направление даёт честный отказ со списком доступных стран. Если названа только сеть отелей без страны, поиск идёт по предположению, но модель обязана об этом сказать.

### 3.10. Прочее

- **Vite перезагружал страницу при поиске** — бэкенд писал отладочный файл внутрь проекта. Журнал вынесен в домашнюю папку (`~/.totus-chat-logs/`).
- **Бесконечное переподключение WebSocket** — хук подписывался на весь стор и пересоздавал сокет на каждый токен.
- **Дубли номеров** — операторы пишут одно название по-разному («STANDARD ROOM LAND VIEW», «Standard Room Land View [b2b]», «STANDART...»). Введён `normalizeRoomKey`.
- **Пустой пузырь в чате** — остался от удалённого блока отладки; сообщения без содержимого больше не рисуются.

## 5. Возможности

**Поиск и подбор.** Свободная формулировка, разбор параметров из фразы, фильтры (звёзды, питание, пляж, линия, цена, удобства), поиск по семействам отелей, ранжирование в стиле Kayak (оптимум / дешевле / лучший рейтинг), по умолчанию 5 карточек, до 10 по просьбе.

**Информация об отеле.** Описание, удобства, пляж, рейтинг, отзывы гостей, номера с питанием и ценами, сравнение отелей по фактам.

**Интерфейс.** Список чатов с возвратом, история переживает перезагрузку, живой статус работы, карточки отелей и номеров, дисклеймеры, ссылки на totus.club.

**Диагностика.** Журнал диалогов с параметрами вызовов, служебные адреса для сырых ответов API, метка версии в логе при старте.

## 6. Настройка

```bash
npm install
cp .env.example .env    # вписать ключи
npm run dev             # фронтенд + бэкенд
npm run typecheck:server
```

Основные переменные:

| Переменная | Назначение |
|---|---|
| `LEVEL_TRAVEL_API_KEY` | Токен партнёра (без обёртки `Token token=`) |
| `DEEPSEEK_API_KEY` | Ключ модели |
| `LLM_MODEL`, `LLM_BASE_URL` | Модель и адрес — переключение на другую модель |
| `LLM_THINKING` | `enabled` вернёт режим размышлений (не рекомендуется) |
| `TOTUS_SITE_URL` | Сайт компании для ссылок |
| `TOTUS_EXCLUDED_COUNTRIES` | Закрытые направления (сейчас `FR,ES,GR,IT`) |
| `TOTUS_LOG_DIR` | Папка журнала (по умолчанию `~/.totus-chat-logs`) |
| `TOTUS_BOOKING_URL_TEMPLATE` | Шаблон ссылки платформы заказа |

Направления сейчас: Турция, Египет, ОАЭ, Таиланд, Вьетнам, Индия, Мальдивы, Бали, Тунис, Кипр, Черногория.

## 7. Метод работы

**Одна правка за раз.** Правило появилось после нескольких случаев, когда пакетные изменения ломали работу и было невозможно понять, какое именно. Каждая версия помечена в `BUILD_TAG` и печатается при старте — так видно, что запущена нужная сборка.

**Диагностика по фактам, а не по догадкам.** Три инструмента дали больше всего: расшифровка `request_id` (нашла проблему с номерами), журнал диалогов (показал, что фильтр не доходит до поиска), браузерная диагностика (поймала падение модели и поиск за 0,3 секунды).

**Архив каждой версии.** Откат возможен на любую точку.

## 8. Открытые вопросы

- **Ссылка бронирования.** `TOTUS_BOOKING_URL_TEMPLATE` пока не настроен под реальную платформу заказа, используется страница отеля.
- **Написание курортов Индии.** Страна работает, курорт `Goa` не проверен на живом API.
- **Голосовой ввод.** Проработан, не внедрён; сторонние AI-сервисы в проект не подключены (модель — только DeepSeek). При внедрении обязательно словарь терминов (бренды, курорты, коды питания) и показ распознанного текста для правки перед отправкой.
- **Локальная модель.** Для 284 млрд параметров нужно 180–200 ГБ памяти; на 100 параллельных диалогов — серверный узел уровня 4×GB300. При текущих объёмах API дешевле. Переключение — три строки в `.env`.
- **Ключи.** Ключи Level.Travel и DeepSeek засветились в переписке — перевыпустить перед продакшеном.

## 9. Что важно не сломать

1. `thinking: {type: 'disabled'}` — без него модель падает после первого же вызова инструмента.
2. Журнал пишется **вне папки проекта** — иначе Vite перезагружает страницу.
3. Проверка типов сервера — отдельный `tsconfig.server.json`, основной конфиг серверный код не видит.
4. Написания городов вылета — через точку (`St.Petersburg`).
5. Название поставщика не должно появляться в клиентских текстах.
6. Модель не имеет права утверждать то, чего нет в данных: отсутствие информации — не отрицание факта.
