# Мила: «сервер прежде всего» — правила и план

**Введено владельцем 08.10.2026** для всех задач по улучшению AI (Мила, totus_ai_v2).

## 1. Правила работы

1. Каждая задача по AI — отдельный Pull Request в `tosmedia/totus_ai_v2` (ветка `claude/<тема>` от `main`).
2. В конце каждой задачи явно пишем, что нужно обновить:
   - **только API** — `git pull && npm run build && pm2 restart totus-ai-api` на сервере, пользователям ничего обновлять не нужно;
   - **API + сайт** — плюс пересборка totus_WEB с новым `@tosmedia/ai-assistant` (без сторов);
   - **API + приложения** — плюс новый `@tosmedia/ai-assistant-native` в totus_APP и релиз в TestFlight / Google Play / RuStore.
3. Логику AI меняем на сервере. В приложение — только то, что без этого невозможно, и так, чтобы следующие изменения того же рода шли уже через API.
4. Сервер всегда совместим со старыми версиями приложения: старые события и поля не удаляются, новые клиенты получают новое по своим `capabilities`.

## 3. План

### Этап 0 — фундамент (один раз; API + приложения)

После него изменения из A1–A10 идут только через API.

Сервер (обратно совместимо, старые приложения работают как раньше):
1. `GET /api/assistant/config` — приветствие, чипы, подписи статусов, тексты UI, тона плашек, флаги функций, лимиты restore; поле `config_version`.
2. WS-сообщение клиента `hello { client, version, capabilities[] }`; без `hello` — считаем старым клиентом.
3. В событии `tool` — поле `label` (готовый текст статуса).
4. Новое событие `blocks` — универсальные блоки, которые клиент умеет рисовать один раз и навсегда: `text`, `card` (картинка, заголовок, подзаголовок, плашки с тоном, цена, действие), `chips` (быстрые ответы), `buttons`, `notice`. Действия: `send`, `open_hotel`, `open_url`, `open_screen`. Неизвестные блоки клиент пропускает. Старым клиентам сервер продолжает слать `tours` / `rooms` / `destinations`.
5. `BUILD_TAG` и хэш коммита в `/api/health`.

Пакеты (`ai-assistant-native`, затем `ai-assistant`):
6. Загрузка `config` при старте + кэш в AsyncStorage + встроенные значения на случай офлайна.
7. Отправка `hello`, отрисовка `blocks`, подпись статуса из `label`.
8. Расширенный рендер текста: ссылки, нумерованные списки, заголовки.
9. Устойчивость: неизвестные события и поля игнорируются без падений.

Выпуск: новый `.tgz` → totus_APP → один релиз в сторы. Сайт — пересборка totus_WEB.

### Дальше — улучшения качества, только API

- набор проверок `npm run check` и eval-набор эталонных диалогов на поддельных LLM / Level.Travel (STATUS D2);
- разбор реальных диалогов из `/api/logs` (staff) → правки промпта и tools;
- точность поиска и фильтров, комментарии к отелям, уточняющие вопросы, работа с ошибками Level.Travel;
- новые виды ответов — через `blocks`, без релиза.

## 4. Что не переносим на сервер

Навигация внутри приложения (`onOpenHotel`, экран `hotelFromAi`), тема, хранение токена — это часть приложения. Сервер управляет ими только через действия в `blocks`.
