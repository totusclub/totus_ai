# Развёртывание проекта «Тотус клуб»

## Самое важное: что такое «модель» и причём тут Vite

Короткий ответ на ваш вопрос: **отдельную модель создавать не нужно — она уже подключена, её достаточно настроить через файл `.env`.** И один момент, который важно понять сразу, чтобы не потерять время.

**Vite собирает только фронтенд** (то, что видит пользователь в браузере: чат, карточки туров, поиск). Сам ИИ-ассистент работает **не в Vite**, а в отдельном Node-сервере (`server/`), который:
- держит системный промпт,
- вызывает модель (Kimi или ваш локальный Qwen),
- ходит в Level.Travel за турами,
- общается с фронтом по WebSocket.

То есть у проекта **две части**, и «развернуть через Vite» означает запустить обе:

```
Браузер  ←→  Vite (фронт, порт 5173)  ←→  Node-сервер (бэк, порт 3010)  ←→  Модель + Level.Travel
```

Модель — это просто адрес API в переменных окружения. Никакого «файла модели» внутри проекта нет и не должно быть.

---

## Шаг 1. Установка

```bash
npm install
```

## Шаг 2. Настройка `.env`

```bash
cp .env.example .env
```

Откройте `.env` и впишите два ключа: для модели и для Level.Travel. Подробности — в комментариях внутри файла.

## Шаг 3. Запуск (разработка)

```bash
npm run dev
```

Эта команда поднимает **обе части сразу** (через `concurrently`):
- фронт (Vite): http://localhost:5173 ← сюда заходите в браузере
- бэк (Node): http://localhost:3010

Проверить, что бэк жив и видит модель: откройте http://localhost:3010/api/health

## Шаг 4. Сборка (продакшн)

```bash
npm run build      # собирает фронт в папку dist/
```

Важно: `npm run build` собирает **только фронт**. В проде нужно отдельно:
1. Раздавать статику из `dist/` (nginx, любой静 хостинг).
2. Запустить бэк как постоянный процесс: `npm run server` (лучше через pm2/systemd).
3. Настроить nginx так, чтобы `/api` и `/ws/assistant` уходили на бэк (порт 3010), а всё остальное — на статику из `dist/`.

## Как переключить модель с Kimi на ваш локальный Qwen

Весь проект написан на OpenAI-совместимом SDK, поэтому смена модели — это **три строки в `.env`, без единой правки кода.**

**Сейчас (Kimi):**
```
MOONSHOT_API_KEY=sk-ваш-ключ
KIMI_BASE_URL=https://api.moonshot.ai/v1
KIMI_MODEL=moonshot-v1-8k
```

**Ваш локальный Qwen через vLLM:**
```
MOONSHOT_API_KEY=local-dummy-key
KIMI_BASE_URL=http://localhost:8000/v1
KIMI_MODEL=Qwen/Qwen3.6-35B-A3B-Instruct-AWQ
```

`MOONSHOT_API_KEY` для локального vLLM может быть любой непустой строкой — он нужен только чтобы SDK не ругался, vLLM его не проверяет. Запускаете vLLM с `--enable-auto-tool-choice --tool-call-parser hermes` (function calling у этого проекта обязателен), и всё работает как есть.

Именно это делает проект удобным для России: убираете зарубежный Kimi, ставите свой Qwen на сервер с 3090 — ни один запрос клиента не уходит за границу, требования 152-ФЗ по трансграничной передаче не затрагиваются.

## Если при запуске что-то не так

- **`LEVEL_TRAVEL_API_KEY is missing`** — не заполнен токен Level.Travel в `.env`.
- **Ассистент отвечает, но без туров** — проверьте токен Level.Travel и его версию API (`LEVEL_TRAVEL_API_VERSION`).
- **`Kimi: OFF` в логах бэка** — не задан `MOONSHOT_API_KEY`; ассистент откатится на простой скриптовый режим без ИИ.
- **Фронт открывается, но чат молчит** — не запущен бэк (порт 3010) или Vite не проксирует WebSocket; в dev это делается автоматически, проверьте что запускали `npm run dev`, а не `npm run dev:web`.
